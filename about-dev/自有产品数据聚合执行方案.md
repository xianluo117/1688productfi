# 自有产品数据聚合执行方案

## 1. 范围

在现有项目中新增独立的自有产品数据模块，接收、保存和查询外部提交的业务结果。

- 本期只新增数据库结构和后端 API，不修改任何前端文件。
- 与现有采集商品表分开，现有接口、采集和后台任务保持不变。
- 不负责业务流程执行、上游数据获取或 Dify 接口接入。
- 不开发删除接口、飞书同步、向量查重、历史审计或任务调度系统。

## 2. 已确认规则

1. 数据分为批次、货号、颜色三层，分别提供新增、部分修改、列表和详情接口。
2. 每次新增都创建新记录并返回数据库 ID；调用方保存 ID，后续通过 ID 修改和查看。
3. 不按 Dify 批次编号、原始货号、新货号或颜色去重，不增加业务唯一约束。
4. 先创建批次，再携带批次 ID 创建货号；创建颜色时携带货号记录 ID。
5. 新货号是可修改的业务字段，不作为表间关联键。修改新货号不会影响颜色归属。
6. 用户名是外部业务归属信息，不绑定现有登录账号。本期不新增账号或权限模块。
7. 修改仅更新实际提交的字段；未提交字段保持不变，显式空值表示清空可空字段。
8. 规格、尺码和图片集合按整个字段替换，不进行内部合并、追加或自动去重。
9. 业务前提是不会同时修改同一条记录；重点支持多个用户、多个任务并发写入不同记录。
10. 不添加版本冲突检测、自动重试或业务状态自动推导。外部系统提交什么结果，本模块就保存什么结果。

注意：重复调用新增接口会产生多条记录，接口不具备重复提交幂等性。

## 3. 数据结构

### 3.1 表与关联

新增批次表、货号表、颜色表，全部使用独立的数据库生成整数主键。

| 表 | 关联 | 必需字段 | 说明 |
|---|---|---|---|
| 批次表 | 无业务父表 | 数据库 ID，由数据库生成 | 保存批次汇总信息 |
| 货号表 | 批次 ID 外键 | 所属批次 ID | 一个批次包含多条货号记录 |
| 颜色表 | 货号记录 ID 外键 | 所属货号记录 ID | 一条货号记录包含多条颜色记录 |

- 三张表均有创建时间和更新时间，采用带时区时间；新增时两者由数据库默认当前时间生成。
- 修改时，后端在更新语句中将更新时间设置为数据库当前时间表达式，由数据库计算时间值；不使用应用服务器时间，不新增数据库触发器。直接绕过接口更新数据库不会自动刷新更新时间。
- 主键、父级关联、创建时间和更新时间均不允许调用方修改。提交时间、运行开始时间属于外部业务时间，由调用方提供，与上述记录时间分开。
- 业务字段允许分阶段补充，未提供的业务信息保留为空，不伪造完成结果。
- 父子关系通过外键保证；本期不提供迁移所属批次或所属货号的操作。
- 颜色所属批次及新货号通过货号表关联获取，不重复维护一份可变新货号。
- 用户名按原方案保留在批次、货号层，独立保存调用方提交值，不自动同步。

### 3.2 业务字段及类型

以下为拟定字段分组，沿用原方案的数据范围。英文命名和集合内部格式在实施前确认，不自行扩展业务字段。

| 层级 | 保存内容 | 存储类型 |
|---|---|---|
| 批次 | Dify 批次编号、用户名、autoimage 批次编号、autoexcel 批次编号 | 文本 |
| 批次 | 提交时间、运行开始时间 | 带时区时间 |
| 批次 | 处理阶段、最终运行结果 | 分开的文本字段 |
| 批次 | 原始货号摘要、两份表格链接 | 分开的文本字段 |
| 批次 | Temu 上传结果、异常信息 | 分开的文本字段 |
| 货号 | 原始货号、来源链接、新货号、用户名 | 分开的文本字段 |
| 货号 | 原始规格、处理后规格、原始尺码、处理后尺码 | 四个独立 JSONB 字段 |
| 货号 | 是否丢弃、丢弃原因 | 可空布尔值、文本 |
| 货号 | 候选图片下载结果及异常、候选生成结果及异常 | 分开的文本字段 |
| 颜色 | 原始颜色、制表标准颜色 | 分开的文本字段 |
| 颜色 | 运行结果、主图视觉结果、生图结果 | 分开的文本字段 |
| 颜色 | 图片 URL 组 | JSONB，不建立图片明细表 |

完成后的运行结果沿用成功、部分失败、失败；未完成时最终结果为空。处理阶段单独保存，不根据子记录自动统计或更新父记录状态。

### 3.3 索引

- 三张表使用主键索引定位单条记录。
- 货号表建立所属批次 ID 与记录 ID 的组合索引。
- 货号表为新货号建立普通非唯一索引，用于跨批次精确查询。
- 颜色表建立所属货号记录 ID 与记录 ID 的组合索引。
- 不预建未确认筛选字段的索引，不为 JSONB 增加检索索引。

## 4. API 设计草案

提供一组独立 API，而非把所有操作塞入同一个接口。建议统一使用 /api/owned-products 前缀。

| 操作 | 方法 | 相对前缀路径 | 说明 |
|---|---|---|---|
| 新增批次 | POST | /batches | 返回新批次完整记录及 ID |
| 修改批次 | PATCH | /batches/{批次ID} | 仅修改提交的业务字段 |
| 批次列表 | GET | /batches | 分页返回批次记录 |
| 批次详情 | GET | /batches/{批次ID} | 返回单条批次记录 |
| 新增货号 | POST | /batches/{批次ID}/items | 创建该批次下的一条货号记录 |
| 货号列表 | GET | /batches/{批次ID}/items | 分页返回该批次下的货号 |
| 修改货号 | PATCH | /items/{货号记录ID} | 仅修改提交的业务字段 |
| 货号详情 | GET | /items/{货号记录ID} | 返回单条货号记录及所属批次 ID |
| 按新货号查询 | GET | /items/by-new-code | 通过查询参数传入新货号，跨全部批次精确匹配，返回所有匹配货号及各自所属批次信息、全部颜色 |
| 新增颜色 | POST | /items/{货号记录ID}/colors | 创建该货号下的一条颜色记录 |
| 颜色列表 | GET | /items/{货号记录ID}/colors | 分页返回该货号下的颜色 |
| 修改颜色 | PATCH | /colors/{颜色记录ID} | 仅修改提交的业务字段 |
| 颜色详情 | GET | /colors/{颜色记录ID} | 返回单条颜色记录及所属货号记录 ID |

### 请求与响应

- 新增和修改请求体只包含对应层级的业务字段；新增子记录的父级 ID 从路径获取。
- 新增成功返回 201；修改和查看成功返回 200；不存在的记录或父记录返回 404。
- 写入事务提交成功后才返回成功响应，不采用后台排队写入。
- 单条响应包含记录 ID、父级 ID（如有）、该层业务字段、创建时间和更新时间。
- 列表响应包含记录集合、总数、页码和每页条数。
- 建议页码从 1 开始、默认每页 30 条、按记录 ID 倒序；分页在数据库中执行。
- 详情只返回当前层，不默认嵌套整批货号和颜色；子层通过列表接口查看。
- 按新货号查询使用独立聚合接口：查询参数为新货号文本，精确匹配，不进行模糊搜索或自动改写货号；查询范围跨全部批次，不按用户名限制。
- 聚合接口返回匹配货号的列表和匹配总数；每项包含货号完整信息、所属批次完整信息和该货号的全部颜色。没有匹配时返回 200、空列表及总数 0。
- 本接口一次返回全部匹配货号，不分页、不截断颜色；其他三层列表仍沿用分页规则。仅返回匹配货号的颜色，不展开同批次其他货号。
- 同一新货号对应多条记录时全部返回，不去重、不合并、不默认只取最新一条；货号按记录 ID 倒序，颜色按记录 ID 升序。
- 聚合查询使用关联查询及批量加载颜色，避免逐条查询；作为只读接口，不锁定业务记录，不影响原有按 ID 查询的单层详情接口。
- 注册路由时将固定路径 /items/by-new-code 放在货号 ID 动态路径之前，避免被当作记录 ID 解析。
- 不因增加查询而为新货号添加唯一约束，也不将新货号改为表间关联键。
- 除新货号查询外，本期不增加其他业务筛选和自定义排序；如需这些能力，先确认字段。
- 使用 FastAPI 自动接口文档展示最终请求、响应和字段说明，不增加前端管理页面。

## 5. 并发写入方案

### 5.1 异步访问与连接池

现有连接为同步模式，见 [`backend/app/database.py`](../backend/app/database.py)。新模块单独增加异步数据库连接和会话工厂，旧模块保持同步模式不变。

- 沿用 FastAPI、SQLAlchemy 2、PostgreSQL、Alembic。
- 使用现有 psycopg 3 驱动的异步能力，不新增数据库服务或更换驱动。
- 数据库请求全程异步等待，不在异步路由里直接调用同步数据库查询。
- 每个请求创建自己的会话，禁止跨请求或并发任务共享会话。
- 只使用 SQLAlchemy 异步引擎自带的连接池，psycopg 只作为异步驱动；不另外创建 psycopg 连接池，不叠加两层池。
- 连接不足时异步等待池中可用连接，等待受连接池超时限制，不阻塞事件循环。
- 应用关闭时释放 SQLAlchemy 异步引擎及其连接池。连接预算按各进程中同步池和异步池的常驻连接上限、溢出连接上限合计，并计入现有工作进程的连接，不无限扩大。
- Windows 原生运行时确认事件循环与 psycopg 异步连接兼容；容器部署沿用现有方式，不为未使用的运行方式增加兼容层。

### 5.2 短事务与独立写入

- 一次新增或修改只操作一条业务记录，一个请求一个事务。
- 每次提交独立成功或失败；某条颜色写入失败，不回滚之前已提交的其他颜色或货号。
- 新增子记录不同时改写父记录状态、统计或更新时间，避免所有子任务争用同一父记录。
- 事务中不执行图片下载、外部 API 调用或其他长耗时任务。
- 使用数据库生成主键，不通过查询最大 ID 分配新 ID。
- 修改直接按主键更新提交字段，不先读取完整记录再整条覆盖。
- JSONB 字段整体赋值，显式空值保存为数据库空值。
- 不使用进程内全局锁、批次锁、消息队列、版本号或串行任务队列。
- 不同记录可并发写入；数据库仍可能因连接容量和自身锁机制发生等待，不承诺无限并发。

### 5.3 同一记录的约定

业务上由调用方避免同一记录并发修改。后端不主动检测或协调这种情况。

若意外发生，同一字段按数据库实际写入顺序覆盖，不保证按请求到达时间或上游业务时间排序；不同字段只更新本次提交部分。此规则不代表能够自动合并同一个 JSONB 字段的多个修改。

## 11. 最终接口约定与验证记录（2026-10-30）

### 11.1 接口使用约定

- 路径、方法和状态码采用第 4 节设计，共 13 个操作。应用启动后通过 /docs 查看完整字段及请求响应结构。
- 三层请求与字段中文说明见 [`schemas.py`](../backend/app/owned_products/schemas.py)。两份链接使用 [`spreadsheet_url_1 / spreadsheet_url_2`](../backend/app/owned_products/schemas.py:23)，仅表示第一份、第二份，不赋予额外业务含义。
- 新货号字段和聚合查询参数均为 [`new_item_code`](../backend/app/owned_products/schemas.py:32)。调用 /api/owned-products/items/by-new-code?new_item_code=货号原文，调用方负责 URL 编码；不裁剪空格或改变大小写。
- 普通列表参数为 page（默认 1）、page_size（默认 30），均为正整数；响应包含 items、total、page、page_size，按 ID 倒序。
- 聚合响应包含 items、total；每项含 item（完整货号）、batch（完整所属批次）、colors（全部颜色）。不分页，货号 ID 倒序，颜色 ID 升序。无匹配返回空集合及总数 0。
- 未提交字段不修改；空请求对象只返回现有记录，不刷新更新时间。显式空值清空可空字段，空字符串按原文保存。对象和数组按整个字段替换，不限制内部结构。
